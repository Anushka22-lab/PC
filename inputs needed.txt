AIOps Lab Input Guide
======================

1. Instruction Manual
----------------------

Use this guide when asking an AI coding agent to complete the AIOps Lab.

- Open the repository in VS Code.
- Paste the master prompt from this file into the coding agent.
- Tell the agent to inspect the repository before editing.
- Provide the repository path if the workspace is not already open.
- Make sure Docker is running for Kafka validation.
- Make sure Git authentication is available if the agent must push changes.
- Use Python 3.10, 3.11, or 3.12 for the best Airflow compatibility.
- Do not provide passwords, API keys, or private tokens in the prompt.
- Ask the agent to run focused tests after each question.
- Ask the agent to commit each question separately and push main only after validation.
- Review the final changed-file list, test results, commit hashes, and Git status.

Recommended environment variables:

KAFKA_BOOTSTRAP_SERVERS=localhost:9092
KAFKA_TOPIC=server_metrics
KAFKA_MESSAGE_COUNT=10
SERVER_ID=server01
CPU_ALERT_THRESHOLD=80
KAFKA_CONSUMER_GROUP=aiops-consumer

2. Sample Questions
-------------------

Sample Question 1:
Create a Python program that generates 20 server metric records, calculates
basic statistics, detects CPU values above 80%, prints the anomalous records,
and saves a chart showing CPU values and anomalies.

Sample Question 2:
Create a Kafka topic named server_metrics and a Python producer that publishes
at least ten JSON messages containing server_id, cpu_usage, memory_usage,
disk_usage, and timestamp. Include Docker Compose setup and retry handling.

Sample Question 3:
Create a Kafka consumer for server_metrics. Validate JSON messages, display
valid metrics, and log ALERT: High CPU detected on server01 when CPU is above
80%. Handle malformed messages safely.

Sample Question 4:
Create an Airflow DAG with the tasks collect_metrics, process_metrics,
detect_anomaly, and generate_report. Use PythonOperator and this order:
collect_metrics >> process_metrics >> detect_anomaly >> generate_report.

Sample Question 5:
Create an integrated AIOps monitor that consumes Kafka metrics, validates them,
detects CPU anomalies, emits alerts, maintains anomaly counts, retries Kafka
failures, and generates a final report.

3. Master Prompt
----------------

You are a senior Python, Kafka, Airflow, Docker, and AIOps engineer.

Work directly in the current repository and complete the entire AIOps Lab in
one go. Inspect the repository and Git history first. Preserve existing work,
avoid duplicate files and commits, and use clean, maintainable, type-hinted
Python code.

General requirements:
- Use environment variables for brokers, topics, thresholds, ports, retries, and IDs.
- Validate all input data before processing.
- Use structured logging and explicit error handling.
- Handle malformed messages, Kafka failures, retries, and clean shutdowns.
- Keep modules independently testable and follow PEP 8.
- Do not expose secrets.
- Keep README.md and requirements.txt synchronized with the implementation.
- Use Docker Compose for reproducible Kafka setup.
- Run focused validation after every question.
- Continue without confirmation unless a real environment blocker occurs.
- Report the exact failed command when an environment blocker occurs.

Question 1:
Create q1_anomaly_detection.py with 20 deterministic server records. Include
timestamps, CPU, memory, and response time. Calculate statistics and detect
CPU anomalies above 80%. The three anomalies must be 10:05 at 95%, 10:12 at
97%, and 10:18 at 92%. Print the results and save a matplotlib chart as
q1_anomalies.png.

Question 2:
Create q2_kafka_setup.py and q2_kafka_producer.py. Create the idempotent
server_metrics topic, generate at least ten JSON metric messages, publish them
with acknowledgements and retries, support environment configuration, and
handle clean shutdown. Add a single-node official Kafka KRaft service in
docker-compose.yml and validate the full publish and consume round trip.

Question 3:
Create q3_kafka_consumer.py. Consume server_metrics, parse and validate
server_id, cpu_usage, memory_usage, disk_usage, and timestamp. Reject malformed
or invalid messages, log valid metrics, alert when CPU is greater than 80%,
treat 80% as normal, retry Kafka errors, and support clean shutdown and bounded
testing.

Question 4:
Create q4_airflow_aiops_dag.py using PythonOperator. Define exactly these tasks:
collect_metrics, process_metrics, detect_anomaly, and generate_report. Use
collect_metrics >> process_metrics >> detect_anomaly >> generate_report. Collect
CPU 87, memory 65, and response time 420ms. Use XCom, retries, retry delay,
scheduling, catchup=False, threshold configuration, and clear logging. Validate
the DAG structurally if Airflow is unavailable.

Question 5:
Create q5_integrated_aiops_monitor.py. Reuse the Question 3 validation and
alert behavior. Consume Kafka metrics, count processed messages and anomalies,
log running and final totals, retry temporary Kafka and broker failures,
support clean signals and max_messages testing, and validate with both fake and
live consumers.

Final verification:
- Compile every Python module.
- Run focused assertions for Questions 1, 3, and 5.
- Validate Docker Compose configuration.
- Start Kafka and run integration tests when Docker is available.
- Run git diff --check.
- Do not commit __pycache__ or unrelated generated files.
- Keep q1_anomalies.png.
- Commit each question separately on main with descriptive messages.
- Push main to origin after validation.
- Report changed files, validation results, commit hashes, final Git status,
  and any limitations.

When using this file as input, replace only the repository-specific values such
as server ID, Kafka host, topic name, and CPU threshold when necessary.
